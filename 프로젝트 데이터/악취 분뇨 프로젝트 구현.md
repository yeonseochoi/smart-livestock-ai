# 악취 분뇨 프로젝트 구현 설명서 (최종판)

팀 구현 매뉴얼 v2 · 2026\-08\-10 · 데모 v1\~v5 검증에서 발견된 이슈 전부 반영 · 이 문서와 "프로젝트 데이터" 폴더만으로 구현 가능

## 프로젝트 한 줄 요약

**"기상 조건과 축산 악취 민원의 관계를 익산시 실제 데이터(2020\~2026)로 학습하여, 기상 예보만으로 민원 위험도를 사전 예측하고 양돈농가에 안전한 작업 시간대를 추천하는 시스템."**

예측은 성격이 다른 두 모듈로 분리된다. 이 구분이 전체 아키텍처의 핵심 원칙이다.

| 모듈 | 담당 질문 | 구현 | 검증 결과 |
| --- | --- | --- | --- |
| 통계 모델 (ML) | **언제** 민원이 나는가 | XGBoost, 민원 데이터 학습 | ✅ 통과 — 랜덤 2.3배, 기후학 대비 \+4.1%p |
| 물리 모델 (플롬) | **어디로** 냄새가 가는가 | Pasquill–Briggs (legacy 재사용) | ⚠️ 기준 근소 미달 — **등급 반영 금지, 참고 정보 전용** |

두 모델은 **곱하지 않는다** (바람·주야간 변수가 겹쳐 이중 계산됨). 캘린더 등급은 ML 단독, 주민 알림 대상은 "플롬 factor\>0 OR 부채꼴" 합집합.

## S0\~S1 — 정제·라벨 테이블

민원: datetime 파싱 → `시군구=='익산시'` 필터(완주군 8.3% 섞임) → `악취종류코드==101` → 좌표 4자리 반올림\+10분 내 중복 제거(→5,563건) → `block=hour//3`.
기상: 결측 3시간 이내 선형보간. **풍향은 sin/cos 인코딩**(359°↔1° 문제). **강수량 빈칸은 결측이 아니라 무강수 0** (기상청 표기 관행).
라벨 테이블: 2020.01\~2026.07 × 하루 8블록 \= 19,208행. 라벨 3안(y\_bin/y\_cnt/y\_sev) 전부 컬럼으로. 양성률 13.2%.
**왜 3시간 블록:** 신고 지연 노이즈 흡수 \+ 서비스 해상도로 충분.

## S2\~S3 — 피처·학습·평가

**피처 (검증 확정):**

- 기상: 기온·습도·풍속·wd\_sin·wd\_cos·강수 — **바람은 익산 AWS(702)**
- 파생: **연속 교차항(야간×풍속, 야간×습도) — 이분법 플래그(calm\<1.5 등) 금지.** 연속 버전이 성능 동급 이상 \+ 예보 오차 ±0.5m/s에 더 강건함이 검증됨
- 시간: block, month\_sin/cos, 요일, 연도
- **금지:** NH₃(예보 없음), 방향성 피처(임의 농가에서 정의 불가 — S8 분석 전용)
- reduced 피처셋(중기예보용): 기온·강수·month·block·요일

**학습·평가 (검증 확정):**

- full/reduced 2모델. XGBoost \+ 로지스틱 베이스라인 \+ **기후학 베이스라인(month×block 평균) 필수 비교** — "성능이 달력 덕 아니냐"는 질문에 대한 답
- 분할: 시계열 고정(train \~2024 / valid 2025 / test 2026). **비교는 동일 월 구성으로**
- 지표: 주간 랭킹 적중률(메인) \+ PR\-AUC \+ ROC\-AUC 병기(첫인상용 — ROC는 불균형에서 후한 지표이므로 질문 들어오면 기후학 증분으로 복귀) \+ 리프트 차트
- 확정 성적: 적중률 0.467 (랜덤 0.20, 기후학 0.427) / PR\-AUC 0.305 / ROC 0.711 / 상위 20% 추천 시 민원 54.9% 포착
- 등급: valid 분위수 컷 3등급(상위 20% 위험 / \~50% 주의 / 낮음)

## S5 — 작업 창 추천

**시점이 아니라 6시간 창을 추천** (TIME\_WEIGHTS 감쇠 가중평균 — legacy 승계).

```
final(t) = window_risk(t) × work_weight[작업유형] × storage_factor(경과일; 14일↑ 1.5 [C])
```

work\_weight 초기값 \[C\]: 분뇨제거 1.3 / 청소 1.1 / 환기·저감시설 1.0 / 액비살포는 배출량 상대비 환산(기준 20톤·표면살포 대비, legacy/emission.py \[A\]).
**플룸 보정 — 검증 결과 반영: `PLUME_GRADE_BUMP = False` 기본 OFF.** 등급을 바꾸지 않고 "참고: 풍하측 민가 N동 (미검증 모델 — 등급 반영 안 함)" 문구만 표시한다. 복원 조건: 농가 실좌표 확보 후 plume\_multi 재검증에서 기준(lift≥1.5 AND 이탈각\<70° AND 풍하측\>60%) 전부 통과 시.

## S6 — RAG \[80% 달성\]

- 청킹: 법령 조문 단위 / 매뉴얼 소제목 단위. 별표는 통째로 1청크
- 임베딩: **jhgan/ko\-sroberta\-multitask 고정** (Chroma 기본 all\-MiniLM은 영어 편향 — 사용 금지, 77%→…의 개선이 실측됨)
- **위계 부스트 (80% 달성의 핵심):** 청크 메타데이터에 법령 위계(법률/시행령/시행규칙/조례/매뉴얼)\+별표 여부를 넣고 query\_type별 부스트. **주의: "위반 신고 절차"(법 조문)와 "과태료 기준"(시행령 별표)을 같은 유형으로 묶으면 부스트 효과가 상쇄된다 — 분리 규칙 필수 (v3에서 실측된 함정)**
- **별표 폴백:** 가축분뇨법 시행령 별표 1\~9는 **법령정보센터 본문 PDF에 내용 자체가 없음** (추출 실패가 아님 — v5에서 규명). 해당 질의엔 "원문 미확보 — law.go.kr 확인" 안내 자동 부착. DOC 원문 확보 시 rag/reingest\_annex.py로 교체
- 거절 규칙: 개별 사안 판단("고발당하나요?")은 법률구조공단(132) 안내. 모든 답변에 조문·출처 필수
- 평가: 35문항 top\-3 적중률 80% 이상 유지. 점수 하락 시 의심 순서: 청킹 → 부스트 규칙 → 모델
- 미결: 냄새 저감 기본 관리 매뉴얼은 스캔본 — OCR 필요

## 확장 플랜 — 익산악취24 센서 농도 데이터(D8) 확보 시

정보공개청구로 기다리던 공기 중 NH₃ 농도 시계열(측정 지점별)이 도착하면 아래를 적용한다. **파이프라인 골격은 바뀌지 않고, "NH₃ 서빙 입력 금지" 원칙도 그대로다.** 기존 코드는 수정하지 않고 확장만 추가한다.

**사전 확인 2가지:** 측정 지점 좌표 포함 여부(실험 4번의 필수 조건), 기존 데이터(2020\~2026)와의 기간 겹침.

**수정 범위:** 폴더에 `05_센서농도\` 추가 → 정제 스크립트 1개(지점·시각·농도) → 라벨 테이블에 y\_odor 컬럼 병렬 추가(서빙 피처 아님) → 아래 실험 4종:

1. **악취 농도↔기상 상관 분석 (근거 보강)**\: 기상↔농도↔민원 3자 상관을 익산 자체 데이터로 산출 — 발표 근거가 보도자료 인용에서 자체 분석으로 격상. 측정소 데이터에 온도·습도·풍향·풍속이 함께 기록되므로 같은 지점·같은 시각의 상관을 직접 잴 수 있다 (S8 분석 1종 추가)
2. **라벨 검증**\: 농도 기반 "물리적 악취 라벨"을 만들어 민원 라벨과 비교 — 한계 목록의 "라벨\=신고 행동 포함" 문제를 정량화
3. **2단계 모델 실험**\: 기상 예보 → 농도 예측 → 민원 예측의 2단 구조. NH₃를 입력받는 게 아니라 중간 단계에서 예측하므로 서빙 가능(원칙 위반 아님). 농도는 연속값이라 학습 신호가 풍부 — 현재 1단계 모델(0.467)과 동일 조건 비교 후 채택 여부 결정
4. **플룸 재검증(유력한 복원 경로)**\: "바람 불 때 풍하측 측정소 농도가 실제로 오르는가" — 신고 행동 노이즈가 없는 물리량으로 플룸을 검증. 통과 시 PLUME\_GRADE\_BUMP 복원 근거가 된다

## 팀 내부 FAQ

**Q. NH₃ 데이터가 있는데 왜 안 쓰나?** 예보가 없어 예측 시점에 넣을 값이 없다. 근거 그래프 전용.
**Q. 플룸은 실패한 건가?** 기준 3개 중 1개 통과·2개 턱밑 미달(이탈각 0.5°, 풍하측 2.4%p 차). 병목은 주소→좌표 오차로 특정됨. 실좌표 확보 시 한 줄 재실행으로 재평가 — 그 전까지 참고 정보 전용.
**Q. 성능이 낮아 보인다?** PR\-AUC 기준선은 0.5가 아니라 양성률 0.13이다. 서비스 지표는 "주간 랭킹" — 상위 20% 추천으로 민원 55%를 포착하며 이는 랜덤의 2.3배. 발표는 "기후학 대비 증분" 프레임으로.
**Q. 왜 실시간이 아니냐?** 예보 자체가 하루 8회 발표라 실시간이 존재하지 않는다. 매일 새벽 사전계산 → 조회 시 즉시 표시 (일기예보 앱 구조).
